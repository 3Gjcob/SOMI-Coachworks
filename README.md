# South Miami Coach Works — website

Bilingual (English/Spanish) static website for South Miami Coach Works / SOMI Coachworks,
5780 SW 68th St, South Miami, FL 33143.

This repository holds the complete original site exported from ChatGPT Sites (version 3,
source commit `415b4feb176efa49c3000d5ed8c2bf8906372a56`). The design, copy, photos, fonts,
animations, mobile layouts and frontend behavior are identical to that export: every original
file is byte-for-byte unchanged, and rebuilding reproduces the same 12 pages exactly.

There is no framework, npm install, backend or database. Pages are generated by a Python
standard-library script and served as plain static files.

## Preview locally

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

Open http://127.0.0.1:8000/ (use `py -3` on Windows). Don't open the HTML files directly via
`file://` — the site uses root-relative paths and fetches `site-config.json`.

## Edit and rebuild

Change copy in `scripts/build-site.py` (or the gallery in `scripts/repair_gallery.py`), then:

```bash
python3 -X utf8 scripts/build-site.py
node --check dist/app.js   # optional syntax check
```

The build rewrites the 12 HTML pages, `sitemap.xml` and `robots.txt`; it leaves CSS, JS, images
and `site-config.json` alone. Don't hand-edit generated HTML — the next build overwrites it.

To confirm nothing has drifted from the original export:

```bash
python3 docs/migration/verify_export.py
```

(It reports `CHANGED` for files edited since the export, such as the generators and pages after the UI refresh — that's expected.)

## Hosting

Upload the **contents of `dist/`** as the root of a domain or subdomain on any static host
(Netlify, Cloudflare Pages, Vercel static, NGINX, etc.):

- Publish directory: `dist`
- Build command: none (or `python3 -X utf8 scripts/build-site.py` if the host has Python)
- Directory index: `index.html`; unknown routes should 404 — no SPA rewrite to the homepage
- No environment variables, secrets or server runtime

`dist/` must sit at a domain root because asset and page links are root-relative (`/assets/…`,
`/es/…`). For a subpath host, `scripts/build-pages.py` writes a copy with those links (and the
canonical origin) rewritten, leaving `dist/` untouched.

### GitHub Pages

`.github/workflows/pages.yml` publishes the site to `https://jacobkalka.github.io/SOMI-Coachworks/`
on every push to the default branch (or `main`), using `scripts/build-pages.py`. One-time setup:
**Settings → Pages → Build and deployment → Source: GitHub Actions**, then re-run the workflow
from the Actions tab.

Before going live on a new domain, change `ORIGIN` in `scripts/build-site.py` (currently
`https://somicoachworks.jkalka28227.chatgpt.site`, no trailing slash) and rebuild — it updates
canonical/hreflang URLs, social-share metadata, structured data, sitemap and robots.

See `docs/migration/SETUP_AND_HOSTING.md` for the full cutover checklist and an NGINX example.

## Search and security

- **Structured data (JSON-LD):** every page describes the business (`AutoBodyShop`: address, hours, phone, languages, service area, services offered), the website and the page. The homepage adds an `FAQPage` built from the visible FAQs; service pages add `Service` and `BreadcrumbList`. Edit these in `business()`, `head()`, `home()` and `detail()` in `scripts/build-site.py`. Validate after changes at https://search.google.com/test/rich-results.
- **Search text:** each page has its own title and meta description (the `SEO` table in `build-site.py`), and the footer lists the areas served. All keyword text is visible on the page. Don't add hidden keyword text; Google treats it as spam.
- **Not included on purpose:** map coordinates (unverified) and a star-rating aggregate (Google doesn't show self-published ratings for local businesses).
- **Sitemap:** pairs each English page with its Spanish version (`hreflang`). Submit `sitemap.xml` in Google Search Console once the site is on its final domain.
- **Security:** every page carries a Content-Security-Policy (only the site's own scripts, styles and fonts; Google for the map; Formspree only if the estimate form is enabled) and a strict referrer policy. There are no inline scripts or event handlers, external links use `rel="noopener noreferrer"`, and `site-config.json` holds no secrets. If you add a new third-party service, add its domain to `CSP` in `build-site.py`.
- **404 page:** `dist/404.html` (not indexed) is served for unknown addresses on GitHub Pages and most static hosts.

## Estimate form

The photo-upload estimate form is built but hidden until a verified provider is configured in
`dist/site-config.json` (Formspree endpoint with `photoUploadsVerified: true`, or a Jotform URL).
Until then visitors see the phone/email contact card. Examples are in
`docs/migration/config-templates/`. Never put API keys in `site-config.json` — it's public.
